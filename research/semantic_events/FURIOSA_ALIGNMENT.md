# 뉴스 분류 모델과 공식 사건 DB 정렬안

FuriosaAI는 추론 실행 환경이고 분류 의미는 모델의 출력 라벨이 결정한다. 따라서
양쪽 파이프라인이 `semantic_event_contract.schema.json`을 공통 계약으로 사용한다.

## 역할 분리

| 뉴스 모델 출력 | 공식 사건 DB 출력 |
|---|---|
| 기사별 사건 후보, 감성, 원인 문장 | 공식 발표·데이터셋 기반 기준 사건 |
| 빠르지만 오탐·중복 가능 | 느리지만 근거와 날짜가 명확 |
| `model_version` 필수 | 원본 문서번호와 공식 URL 필수 |

두 결과를 제목 문자열만으로 합치지 않는다. 다음 키를 순서대로 사용한다.

1. 공식 문서번호·원문 URL의 직접 일치
2. `taxonomy_code + 핵심 entities + event_time` 근접 일치
3. 임베딩/모델 유사도는 후보 생성에만 사용
4. 확신도가 낮거나 서로 충돌하면 별도 사건으로 유지하고 검수 대기

## 공통 필수 판단 기준

- `taxonomy_code`: GEO 또는 POL 계층 코드
- `event_time`: 실제 발생 시점. 알 수 없으면 null
- `first_seen_at`: 시스템이 처음 알 수 있었던 시점. look-ahead 방지 기준
- `entities`: 행위자, 대상 국가·기관·산업·원자재
- `impact_channels`: 공급망·원자재·환율·금리 등 Numeric 축 연결 통로
- `confidence`: 분류 확신도이지 시장 영향 확률이 아님
- `evidence`: 판단을 다시 확인할 수 있는 URL과 근거 필드

## 합의가 필요한 항목

- 팀 뉴스 모델의 현재 라벨 목록과 점수 범위
- 감성의 대상(기사 문조 / 사건 자체 / 특정 자산 영향)
- 모델이 뽑는 entity 코드 체계(국가는 ISO, 산업은 팀 표준 필요)
- 동일 사건 병합 임계값과 사람 검수 기준

특히 `sentiment`는 공식 사건의 속성으로 강제하지 않는다. 같은 제재도 기업·국가·
원자재별 영향 방향이 다르므로, 대상이 없는 단일 긍정/부정 점수는 분석에 오해를
만들 수 있다.
